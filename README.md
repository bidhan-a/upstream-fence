# Counter Program CU Diff

The same counter program costs 56 CU when built with `cargo-build-sbpf` and 54 CU when built with `cargo-build-sbf`. The difference
is due compiler code generation.

## The two issues

1. An extra jump in pinocchio's entrypoint: The test passes exactly one account to the program.
   Pinocchio's entrypoint handles the first account inline, then reads the instruction data and
   program id after which it performs validation.
   - cargo-build-sbpf: the "read instruction data" code ends up far away from the validation logic so execution must jump across the gap to reach it. That jump costs 1 CU.
   - cargo-build-sbf: the same "read instruction data" code sits right next to the validation logic so execution just continues into it. No jump is needed.

    ```
    (cargo-build-sbpf)                           (cargo-build-sbf)
    libupstream_fence.s, lines 177-182           upstream_fence.s, lines 283-288
    ─────────────────────────────────────────    ─────────────────────────────────────────
    jmp_0470:                                    jmp_0730:              
      ldxdw r6, [r3+0x0]                         ldxdw r5, [r4+0x0]   
      add64  r3, 0x8                             add64  r4, 0x8       
      mov64  r7, r3                              mov64  r0, r4
      add64  r7, r6                              add64  r0, r5  // continues into validation logic below
      ja    jmp_05f8       // extra 1 CU used    // validation logic..
      ...                                         
      ...
      jmp_05f8:
        // validation logic..                                           
    ```
    **Cost: net +1 CU for cargo-build-sbpf.**

2. The program's add and store logic in `checked_add(...).ok_or(ArithmeticOverflow)`
   and the borrow guard from `try_borrow_mut()` are compiled into different machine code that achieves the same result (store 42, return success)
   but the machine code generated by `cargo-build-sbpf` ends up consuming 1 CU more.

    ```
      (cargo-build-sbpf)                            (cargo-build-sbf)
      libupstream_fence.s, lines 274-280            upstream_fence.s, lines 319-324
      ──────────────────────────────────────────   ──────────────────────────────────────────
      jmp_06e8:                                    jmp_0840:
        mov32 r2, 0x17                                jeq  r4, 0x1, jmp_0b60
        and32 r4, 0x1                                 stxdw [r1+0x60], r2
        jne32 r4, 0x0, jmp_0718                       stb  [r1+0x8], 0xff
        stxdw [r1+0x60], r3                           mov64 r0, 0x0
        mov64 r0, 0x0                                 ja jmp_0888
        ja jmp_0728       
    ```
    **Cost: net +1 CU for cargo-build-sbpf.**
